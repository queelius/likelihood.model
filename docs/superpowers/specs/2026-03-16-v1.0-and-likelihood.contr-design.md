# likelihood.model v1.0.0 + likelihood.contr Design Spec

## Context

`likelihood.model` is an R package for likelihood-based statistical inference
in the Fisherian tradition. It defines a "concept" (abstract interface) for
likelihood models and provides generics, default methods, and inference
machinery. It is part of a broader ecosystem of R packages for reliability
engineering and survival analysis.

The current v0.10.0 mixes two concerns:

1. **The concept + inference**: what a likelihood model is, how to fit it,
   how to do Fisherian inference with it
2. **The contribution builder**: constructing likelihood models from
   heterogeneous observation types (exact, censored, masked, etc.)

Downstream packages (maskedcauses, flexhaz, maskedhaz) use concern #1
extensively but implement their own models via simple S3 classes. They
do not use the R6 `likelihood_contr_model` builder. The contribution builder
has value as an abstraction but does not belong in the foundation layer.

## Decision

Split into two packages:

- **`likelihood.model` v1.0.0**: the concept + inference (stable foundation)
- **`likelihood.contr`**: the contribution builder (new package)

## Package 1: likelihood.model v1.0.0

### What It Is

The minimal, stable foundation layer. Defines what a likelihood model is and
what you can do with one. No builders, no R6, no contribution machinery.

### Exports (~25 symbols)

**Concept:**
- `is_likelihood_model(x)`: test if object satisfies the concept

**Generics + defaults:**
- `loglik(model, ...)`: returns `function(df, par, ...)`
- `score(model, ...)`: returns `function(df, par, ...)`; default uses `numDeriv::grad`
- `hess_loglik(model, ...)`: returns `function(df, par, ...)`; default uses `numDeriv::hessian`
- `fim(model, ...)`: returns `function(theta, n_obs, ...)`; default uses MC negative expected Hessian
- `rdata(model, ...)`: returns `function(theta, n, ...)`
- `assumptions(model, ...)`: returns character vector (direct value, not closure)
- `loglik.likelihood_model`: clear error for unimplemented concept
- `rdata.likelihood_model`: clear error for unimplemented concept

**Fitting:**
- `fit.likelihood_model(object, ...)`: optim-based MLE solver, returns closure
- `sampler.likelihood_model(x, df, par, ...)`: bootstrap sampling distribution

**Result classes:**
- `fisher_mle(par, vcov, loglik_val, ...)`: MLE result object
- `fisher_boot(boot_result, original_mle)`: bootstrap MLE result
- Full S3 method suite: `coef`, `vcov`, `confint`, `logLik`, `nobs`, `print`,
  `summary`, `se`, `bias`, `mse`, `params`, `nparams`, `observed_fim`,
  `sampler`, `score_val`, `obs`

**Fisherian inference:**
- `support(x, ...)`: log relative likelihood
- `relative_likelihood(x, ...)`: likelihood ratio
- `likelihood_interval(x, ...)`: pure likelihood interval
- `profile_loglik(x, ...)`: profile likelihood
- `evidence(model, ...)`: evidence for theta1 vs theta2 (S3 generic)
- `lrt(null, alt, ...)`: likelihood ratio test, returns `lrt_result`
- `deviance.fisher_mle(object, ...)`

**Deprecated (kept for backward compatibility):**
- `observed_info(model, ...)`: deprecated, use `-hess_loglik(model)(df, par)`.
  Retained because maskedcauses imports and re-exports it. Will be removed
  in a future version after maskedcauses migrates.

**Example implementation:**
- `exponential_lifetime(ob_col, censor_col)`: closed-form MLE, analytical
  score/Hessian/FIM, right-censoring support, `rdata()` for MC validation

### Dependencies

**Imports:** `algebraic.mle (>= 2.0.0)`, `generics`, `stats`, `numDeriv`, `boot`
**Suggests:** `mvtnorm`, `algebraic.dist`, `testthat`, `knitr`, `rmarkdown`

No `R6` dependency.

## Package 2: likelihood.contr

### What It Is

A package for constructing likelihood models from heterogeneous observation
types. You declare contribution types, provide a log-likelihood function for
each, and it composes them into a `likelihood_model` that plugs into all of
`likelihood.model`'s inference machinery.

### Core API (3 functions)

#### `contr_name(dist_name, type, ob_col = "x", ob_col_upper = NULL)`

Generates a contribution from a standard R distribution using the `d<name>`
(PDF) and `p<name>` (CDF) naming convention.

**Arguments:**
- `dist_name`: distribution name (e.g., `"weibull"`, `"norm"`, `"exp"`)
- `type`: one of `"exact"`, `"right"`, `"left"`, `"interval"`
- `ob_col`: column name for observations
- `ob_col_upper`: column name for upper bound (interval censoring only)

**Returns:** An S3 object of class `"contr"` containing a `loglik` function.

**Log-likelihood formulas by type** (using `log = TRUE` / `log.p = TRUE`
where available for numerical stability):
- `"exact"`: `sum(d<name>(x, ..., log = TRUE))`
- `"right"`: `sum(p<name>(x, ..., log.p = TRUE, lower.tail = FALSE))`
- `"left"`: `sum(p<name>(x, ..., log.p = TRUE))`
- `"interval"`: `sum(log(p<name>(x_upper, ...) - p<name>(x_lower, ...)))`

Score and Hessian fall back to `numDeriv` (numerical differentiation).

**Parameter matching:** The parameter vector `par` is mapped to distribution
function formals by position or name. Formals `x`, `q`, `p`, `n`, `log`,
`log.p`, `lower.tail`, and `...` are excluded from matching. An error is
raised if `par` has more elements than the distribution accepts. This
follows the same logic as the current `prepare_args_list()` in
`likelihood_name_model`.

#### `contr_fn(loglik, score = NULL, hess = NULL)`

Wraps a user-provided log-likelihood function (and optional derivatives)
into a contribution object.

**Arguments:**
- `loglik`: required, `function(df, par, ...)`
- `score`: optional, `function(df, par, ...)`; falls back to `numDeriv::grad`
- `hess`: optional, `function(df, par, ...)`; falls back to `numDeriv::hessian`

**Returns:** An S3 object of class `"contr"`.

#### `likelihood_contr(obs_type, ..., rdata_fn = NULL, assumptions = "iid")`

Composes named contributions into a likelihood model.

**Arguments:**
- `obs_type`: either a string (column name to dispatch on) or a function
  `function(df) -> character vector` (one type label per row)
- `...`: named contributions. Names must match the values produced by
  `obs_type`. Each value is a `"contr"` object from `contr_name()` or
  `contr_fn()`.
- `rdata_fn`: optional `function(theta, n, ...)` for random data generation.
  Required for `fim()` to work on this model. If not provided, `rdata()`
  errors with a clear message.
- `assumptions`: character vector of assumptions. The `"iid"` assumption is
  always injected regardless of user input, since the summation of
  contributions requires it.

**Returns:** An S3 object of class `c("likelihood_contr", "likelihood_model")`.
The class `likelihood_contr` matches the constructor, following the R
convention where classes share names with their constructors.

**S3 methods provided:**

`loglik.likelihood_contr(model, ...)` returns a function that:
1. Splits `df` by `obs_type`
2. Calls each contribution's `loglik` on its subset
3. Sums the results (i.i.d. assumption)

`score.likelihood_contr(model, ...)` and `hess_loglik.likelihood_contr(model, ...)`
follow the same split-dispatch-sum pattern. Each contribution uses its own
score/hess function if provided via `contr_fn()`, or falls back to
`numDeriv` independently. This is more efficient than differentiating the
composite log-likelihood because each contribution operates on a smaller
data subset.

**Caching:** The returned closure caches the data split. Cache is
invalidated when `identical(df, cached_df)` is `FALSE`.

**Edge cases:**
- If `obs_type` is a string and the column does not exist in `df`: error.
- If a type value in the data has no matching contribution: error listing
  unmatched values.
- If `obs_type` column contains `NA`: error.
- If a contribution type has zero rows after splitting: contributes 0 to
  the log-likelihood, zero vector to score, zero matrix to Hessian. This is
  handled at the `likelihood_contr` level, not delegated to contributions.

### Usage Examples

```r
library(likelihood.model)
library(likelihood.contr)

# Example 1: Weibull with right-censoring
model <- likelihood_contr(
  obs_type = "status",
  exact = contr_name("weibull", "exact", ob_col = "time"),
  right = contr_name("weibull", "right", ob_col = "time")
)

df <- data.frame(
  time   = c(rweibull(80, 2, 1), rep(2, 20)),
  status = c(rep("exact", 80), rep("right", 20))
)

result <- fit(model)(df, par = c(shape = 1.5, scale = 0.8))
summary(result)

# Example 2: Custom contribution for masked data
masked_ll <- contr_fn(
  loglik = function(df, par, ...) {
    # custom log-likelihood for masked observations
    ...
  }
)

model <- likelihood_contr(
  obs_type = "type",
  exact  = contr_name("weibull", "exact", ob_col = "t"),
  masked = masked_ll
)

# Example 3: Function-based dispatch
model <- likelihood_contr(
  obs_type = function(df) ifelse(df$delta == 1, "exact", "right"),
  exact = contr_name("exp", "exact", ob_col = "t"),
  right = contr_name("exp", "right", ob_col = "t")
)
```

## Migration Path

### For likelihood.model users

v0.10.0 to v1.0.0 is a breaking change. Users of:

| v0.10.0 feature | v1.0.0 migration |
|-----------------|-----------------|
| `likelihood_contr_model$new(...)` | `likelihood_contr(...)` from `likelihood.contr` |
| `likelihood_name("weibull", ...)` | `likelihood_contr(... = contr_name("weibull", ...))` from `likelihood.contr` |
| `weibull_uncensored("x")` | `contr_name("weibull", "exact", ob_col = "x")` composed via `likelihood_contr()` |
| `observed_info(model)` | `-hess_loglik(model)(df, par)` (deprecated but still available in v1.0.0) |

### For downstream packages

**maskedcauses**: must update its re-export of `observed_info` before
`likelihood.model` removes it in a future version. No other changes needed.

**flexhaz, maskedhaz**: no changes required. These packages implement the
`likelihood_model` concept directly via S3 classes and depend only on the
generics and inference machinery, which are unchanged.

1. **Create `likelihood.contr` package**: scaffold, implement `contr_name`,
   `contr_fn`, `likelihood_contr`, tests, vignettes
2. **Strip `likelihood.model` to v1.0.0**: remove extracted code, update
   DESCRIPTION, rewrite vignettes, rewrite tests to use `exponential_lifetime`
3. **Test `likelihood.contr` against v1.0.0**: re-run `likelihood.contr`
   tests to verify they work against the stripped `likelihood.model`

   build and pass tests against `likelihood.model` v1.0.0
5. **Update r-universe**: add `likelihood.contr` to packages.json

   is accepted)
7. **Submit `likelihood.contr` to CRAN** (after likelihood.model v1.0.0 is
   accepted)
